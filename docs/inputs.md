# Text input

Inputs allow users to enter and edit text in interfaces. They are essential for forms, search fields, and data entry within the BUSUP ecosystem.


import { TextInput } from '@site/src/components/HomepageFeatures/DS/TextInput';

## Component States

Below you can see the different input states, consuming our Design Tokens directly from the global CSS.


### Default / Active
The standard state for data entry. Click the field to see the focus (active) state.
<TextInput 
  label="Full Name" 
  placeholder="e.g. John Doe" 
  hint="Enter your name as it appears on your ID."
/>


### With Icon
Inputs can also include visual cues to help users identify the expected data.
<TextInput 
  label="Search Route" 
  placeholder="Enter city or code..." 
  icon="🔍"
  hint="Try searching by the route number."
/>


### Error
Used when data validation fails or a field is required but left empty.
<TextInput 
  label="Email Address" 
  placeholder="user@domain" 
  state="error"
  hint="Please enter a valid email address."
  required={true}
/>


### Disabled
Used when a field is locked and cannot be edited by the user.
<TextInput 
  label="Route ID" 
  placeholder="RT-192" 
  state="disabled"
  hint="This field is automatically generated by the system."
/>

## Dropdown

A Dropdown extends the Text Input with a chevron icon and a selection list. Use when the user must choose one option from a predefined set.

  placeholder="Select an option"
  hint="Choose the route that applies."

<Dropdown

  options={['Economy', 'Business', 'First Class']}

## Component API

The `TextInput` component accepts the following properties:

| Property | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `label` | `string` | - | The text displayed above the input field. |
| `placeholder` | `string` | - | Hint text displayed inside the field before the user types. |
| `hint` | `string?` | - | (Optional) Supplementary text providing context or error feedback below the field. |
| `state` | `'default' \| 'error' \| 'disabled'` | `'default'` | Controls the visual state and behavior of the input. |
| `required` | `boolean` | `false` | If true, displays a red asterisk next to the label. |
| `icon` | `string` | - | An optional icon or emoji to display inside the field. |



## Best Practices

* **Labels:** Keep them short and clear. Avoid using placeholders as labels.
* **Hints:** Use hints to provide extra context (e.g., "Password must be 8 characters").
* **Validation:** Use the Error state as soon as the user finishes typing an invalid entry.
* **Required Fields:** Only mark fields as required if they are strictly necessary for the process.
